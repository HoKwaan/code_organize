@@ linux-d2-sec1-1
Hyper-V 가 켜진 Windows 에서 VirtualBox VM 이 잠든 뒤 제때 깨어나지 못하는 증상의 예다. `./jitter -n 2000` 의 최대 지연이 1.8초나 되고, `dmesg` 에 "clocksource: Long readout interval" 경고가 보인다. 시계(clock_gettime)는 정확하고 프로세스가 늦게 깨어났을 뿐이다. 원인은 VirtualBox 가 Hyper-V 위(NEM 모드, 초록 거북이 아이콘)에서 돌기 때문이다.

@@ linux-d2-sec1-2
VM 의 vCPU 가 호스트에 의해 멈추는지 감시하는 프로그램이다.
- CPU 를 쉬지 않고 돌며 `clock_gettime(CLOCK_MONOTONIC)` 을 연속으로 읽는다. `ns()` 는 timespec 을 나노초 하나로 바꾼다.
- 연속 두 번 읽은 사이(gap)가 5 ms 이상이면 그동안 실행되지 못한 것이므로 횟수 · 최대 · 합계를 기록하고, 처음 15번은 시점과 길이를 출력한다.
- 끝에 멈춤 횟수와 최대값으로 정상 / 가벼움(20 ms 미만) / 심각을 판단한다.
게스트 안에 경쟁자가 없는데도 멈춤이 자주 생기면 호스트(Windows · Hyper-V)가 vCPU 를 멈춘 것이다.

@@ linux-d2-sec1-3
점검 순서다. `make -s` 로 jitter · stallwatch 를 조용히 빌드한다. 쉬지 않는 stallwatch 는 거북이 모드여도 0회로 나올 수 있고, 잠드는 jitter 의 최대 지연이 수 ms 이하면 정상, 100 ms 이상이면 Hyper-V 문제다. 문제는 주로 잠든 뒤 깨어날 때 생기기 때문이다.

@@ linux-d2-sec1-4
Windows 관리자 PowerShell 에서 하이퍼바이저를 켜는 원인을 진단하는 명령이다.
- `Get-WindowsOptionalFeature … Microsoft-Hyper-V-All` / `VirtualMachinePlatform`: Hyper-V 와 가상 머신 플랫폼(WSL2) 기능이 켜졌는지 (이름은 한 번에 하나만).
- `Get-CimInstance … Win32_DeviceGuard`: VBS(가상화 기반 보안) 상태와 실행 중인 보안 서비스(메모리 무결성 등).

원인별로 끄고 재시작해 VBS 상태가 0 이 될 때까지 반복한다.

@@ linux-d2-sec1-8
오늘의 질문을 숫자로 확인한다. `nproc` 은 vCPU 2개, `ps -e --no-headers | wc -l` 은 지금 프로세스 수(수백 개), `cat /proc/loadavg` 는 1 · 5 · 15분 평균 실행 대기 수다. CPU 2개를 수백 개 프로세스가 나눠 쓰므로 커널이 짧은 시간마다 실행할 프로세스를 바꾸는 컨텍스트 스위치가 일어난다.

@@ linux-d2-sec1-t5

@@ linux-d2-sec1-5
진단 결과에 따라 하이퍼바이저를 켜는 원인을 하나씩 끄는 관리자 PowerShell 명령이다.
- A: `Disable-WindowsOptionalFeature` 로 Hyper-V 와 가상 머신 플랫폼(WSL2) 기능을 끈다 (-NoRestart 로 재시작은 나중에).
- B: `reg add` 로 메모리 무결성(HVCI) Enabled = 0, Credential Guard(LsaCfgFlags) = 0.
- C: System Guard Secure Launch Enabled = 0.

- E: `bcdedit /set "{current}" hypervisorlaunchtype off` 로 부팅 때 하이퍼바이저를 올리지 않게 하고 확인한다.
`/t REG_DWORD /d 0 /f` 는 DWORD 형식 값 0 을 확인 없이 덮어쓴다는 뜻이다.

@@ linux-d2-sec1-6

@@ linux-d2-sec1-7
하이퍼바이저를 끌 수 없는 PC 에서 VM 안에 `idle=poll` 커널 옵션을 넣는 방법이다. `sed -i` 로 /etc/default/grub 의 GRUB_CMDLINE_LINUX_DEFAULT=" 바로 뒤(`&` 는 찾은 문자열)에 idle=poll 을 끼워 넣고 `update-grub` 후 재부팅한다. vCPU 가 쉬지 않아 깨어나기 지연이 사라지지만 호스트 코어를 계속 100% 쓴다. 실습 후에는 두 번째 줄로 옵션을 지우고 되돌린다.

@@ linux-d2-sec1-9
잠드는 프로그램과 계속 도는 프로그램의 컨텍스트 스위치 수를 비교한다.
- `status_value(key)` 는 /proc/self/status 에서 key 줄을 찾아 콜론 뒤 숫자를 `atol` 로 돌려준다.
- 시작 전후로 `voluntary_ctxt_switches`(스스로 잠든 횟수)와 `nonvoluntary_ctxt_switches`(선점당한 횟수)를 읽어 차이를 출력한다.
- sleep 모드는 `usleep(1000)` 을 1000번 해서 매번 스스로 CPU 를 내려놓는다.
- busy 모드는 `now_sec()`(CLOCK_MONOTONIC 초)로 2초 동안 `volatile` 변수를 계속 증가시킨다. volatile 이라 최적화로 루프가 사라지지 않는다.
자발적은 sleep · I/O 대기로 스스로 내려놓는 것, 비자발적은 할 일이 남았는데 스케줄러가 빼앗는(선점) 것이다.

@@ linux-d2-sec1-11

@@ linux-d2-sec1-12
두 전환 횟수를 읽는 빈칸 채우기다.
- 빈칸 ① `voluntary_ctxt_switches`: 스스로 잠들어 CPU 를 내려놓은 횟수.
- 빈칸 ② `nonvoluntary_ctxt_switches`: 할 일이 남았는데 선점당한 횟수.
- 빈칸 ③ `usleep`: 1000µs = 1 ms 잠드는 호출. 부를 때마다 자발적 전환이 하나씩 늘어 1000 이 된다.

@@ linux-d2-sec1-t2
하이퍼바이저 진단 결과별 원인과 할 일 표다.
- Hyper-V-All · VirtualMachinePlatform 이 Enabled → Hyper-V · WSL2 기능 → A.
- VirtualizationBasedSecurityStatus : 2 → VBS 실행 중. 이것만 남아도 거북이 모드라 서비스 번호로 판단한다.

@@ linux-d2-sec1-t3

@@ linux-d2-sec2-1
CFS 의 핵심 식이다. vruntime 증가량 = 실제 실행 시간 × (1024 / weight). weight 가 클수록(nice 가 낮을수록) vruntime 이 천천히 늘어 더 자주 뽑힌다. 스케줄러는 레드블랙 트리에서 vruntime 이 가장 작은 맨 왼쪽 태스크를 고른다. nice 가 1 오를 때마다 weight 는 약 1.25 배 줄어든다. 커널 6.6 부터는 EEVDF 로 바뀌었지만 weight 비율로 나누는 결과는 같다.

@@ linux-d2-sec2-2
예제 02 `02_nice_race.c` 다. nice → weight 표(WEIGHT)를 두고, 두 자식이 함께 쓰는 카운터를 mmap 공유 메모리에 만든다. fork 한 두 자식을 `sched_setaffinity` 로 CPU 0 하나에 묶어 같은 CPU 를 두고 경쟁하게 하고, 자식 B 는 `setpriority` 로 nice 를 올린다. 0.2초 뒤 동시에 출발해 3초 동안 카운트한 뒤, 실제 비율과 weight 로 계산한 기대 비율을 나란히 출력한다.
