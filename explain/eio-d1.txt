@@ eio-d1-sec4-1

@@ eio-d1-sec4-3
호스트 이름을 확인하고 고치는 명령이다. USB 망은 PC 1대와 Pi 1대만 이어지므로 40대가 같은 이름과 IP 를 써도 괜찮다. 하지만 Wi-Fi 망에서는 40대가 한 망에 있어 이름이 겹치면 나중 보드가 rpi-07-2.local 로 밀리고 남의 보드에 접속하게 된다. 그래서 Wi-Fi 에 붙기 전에 정리한다.
- `hostname`: 지금 이름을 출력한다. 좌석 번호(rpi-07)인지 본다.
- `sudo raspi-config nonint do_hostname rpi-07`: 메뉴 없이 이름을 바꾼다. /etc/hostname 과 /etc/hosts 를 함께 고친다.
- `sudo reboot`: 새 이름을 적용한다. 1분 뒤 PuTTY 로 다시 접속한다.

@@ eio-d1-sec4-4
인터넷 없이 USB 접속만으로 보드 상태를 점검하는 명령이다.
- `grep CODENAME /etc/os-release`: OS 버전 이름이 `trixie` 인지 확인한다.
- `uname -m`: CPU 아키텍처가 `aarch64`(64-bit)인지 확인한다.
- `timedatectl | grep "Time zone"`: 시간대가 Asia/Seoul 인지 본다.
- `ip -4 addr show usb0`: USB 랜카드 usb0 의 IPv4 주소(10.12.194.1/28)를 본다.
- `vcgencmd get_throttled`: 전압 부족이나 과열로 속도가 제한된 기록이다. PC USB 전원이면 0x50005 처럼 0x0 이 아닐 수 있고, 4-7 에서 어댑터로 바꾼 뒤 다시 본다.
- `vcgencmd measure_temp`: SoC 온도(예: 45.2'C).
- `df -h /`: 루트 파일시스템(SD 카드 `/dev/mmcblk0p2`) 사용량. SD 카드도 /dev 아래의 장치 파일로 보인다.

@@ eio-d1-sec4-6
nmcli 로 Wi-Fi 에 접속하는 순서다. Trixie 는 네트워크를 NetworkManager 가 관리한다.
1. `do_wifi_country KR` 로 국가 코드를 먼저 정한다. 없으면 무선이 rfkill 로 막혀 AP 목록이 비어 있다. `nmcli radio wifi` 가 disabled 면 `sudo nmcli radio wifi on` 으로 켠다.
2. `nmcli dev wifi rescan` 으로 다시 검색하고, `nmcli dev wifi list` 로 주변 AP 를 본다.
3. `nmcli dev wifi connect "SSID" password "PW"` 로 접속한다. 성공하면 설정이 저장되어 재부팅 후에도 자동으로 연결된다. 숨김 SSID 는 끝에 `hidden yes` 를 붙인다.
4. `nmcli dev status` 에서 wlan0 이 connected 인지 보고, `ip -4 addr show wlan0` 으로 받은 IP(예: 192.168.0.37)를 적어 둔다.

@@ eio-d1-sec5-1
raspi-config 를 명령(nonint) 모드로 실행해 인터페이스를 켠다. 여기서는 0 이 켜기, 1 이 끄기다(셸 종료 코드 관례와 같다).
- `do_i2c 0`: I2C 를 켠다 → /dev/i2c-1 (Day 4).
- `do_spi 0`: SPI 를 켠다 → /dev/spidev0.0 (Day 4).
- `do_serial_hw 0`: UART 하드웨어를 켠다 (Day 4).
- `do_serial_cons 1`: 시리얼 로그인 콘솔은 끈다. UART 를 우리 프로그램이 써야 하기 때문이다.

raspi-config 가 실제로 하는 일은 config.txt 와 cmdline.txt 를 고치는 것이다. 기대 출력 그림처럼 기본 설명서(bcm2711-rpi-4-b.dtb)에 `dtparam` 과 `dtoverlay` 가 더해져 최종 Device Tree 가 되고, 커널이 드라이버를 probe 해 /dev 와 /sys 에 장치를 만든다.

@@ eio-d1-sec5-3
config.txt 를 고치기 전에 `.bak` 으로 백업하고 nano 로 연다. PWM 과 UART 핀 배정은 raspi-config 메뉴에 없어 직접 적어야 한다. Trixie 에서 파일 위치는 /boot/firmware/config.txt 다. nano 에서 저장은 Ctrl+O → Enter, 나가기는 Ctrl+X 다.

@@ eio-d1-sec5-4
config.txt 맨 끝 `[all]` 구역의 최종 모습이다. 위 세 줄(`dtparam=i2c_arm=on`, `dtparam=spi=on`, `enable_uart=1`)은 5-1 의 raspi-config 가 넣은 줄이다. 직접 추가하는 두 줄은 다음과 같다.
- `dtoverlay=pwm-2chan`: GPIO18 을 PWM0, GPIO19 를 PWM1 로 바꾼다 (Day 3).
- `dtoverlay=disable-bt`: 블루투스를 끄고 정확한 UART(PL011)를 GPIO14 · 15 로 옮긴다 (Day 4).

config.txt 는 줄 끝 주석을 지원하지 않는다. 주석은 반드시 `#` 으로 시작하는 별도 줄에 쓴다.

@@ eio-d1-sec5-5
`disable-bt` 와 짝이 되는 명령이다. 블루투스 UART 서비스(hciuart)를 끄지 않으면 부팅 중 오류가 난다. config.txt 는 부팅 때 한 번만 읽히므로 `sudo reboot` 으로 반영한다.

@@ eio-d1-sec5-6
재부팅 후 인터페이스가 켜졌는지 확인한다.
- `ls /dev/i2c-* /dev/spidev* /dev/serial0`: I2C(i2c-1), SPI(spidev0.0 · 0.1), UART(serial0) 장치 파일이 생겼는지 본다. i2c-20 · 21 은 HDMI 용이라 쓰지 않는다.
- `ls /sys/class/pwm/`: pwmchip0 이 보이면 pwm-2chan overlay 가 적용된 것이다.
- `ls -l /dev/serial0`: `-> ttyAMA0` 이면 PL011 이 GPIO 에 연결된 것이다. ttyS0 이 보이면 disable-bt 가 반영되지 않았다.
- `cat … cmdline.txt | tr ' ' '\n' | grep console`: 커널 인자를 한 줄씩 나눠 console 항목만 본다. `console=tty1` 만 남아야 하고, `console=serial0,115200` 이 있으면 콘솔 끄기가 안 된 것이다.

@@ eio-d1-sec5-8
빈칸 5-1 의 정답이다. nonint 모드에서는 0 이 켜기, 1 이 끄기다.
- 빈칸 ① `nonint`: 메뉴 없이 명령(non-interactive) 모드로 실행한다.
- 빈칸 ② `do_spi`: SPI 를 켜는 항목 이름이다.
- 빈칸 ③ `0`: UART 하드웨어를 켠다.
- 빈칸 ④ `1`: 시리얼 로그인 콘솔을 끈다. 콘솔이 켜져 있으면 커널 로그와 로그인 프롬프트가 UART 로 나가 Day 4 의 ESP32 통신을 방해한다.

@@ eio-d1-sec5-10
빈칸 5-2 의 정답이다.
- 빈칸 ① `pwm-2chan`: GPIO18 을 PWM0, GPIO19 를 PWM1 로 바꾼다. `pin=` · `pin2=` 인자로 다른 핀을 고를 수도 있다.
- 빈칸 ② `disable-bt`: 블루투스를 끄고 PL011 UART 를 GPIO14 · 15 로 옮긴다. `sudo systemctl disable hciuart` 도 함께 해야 부팅 중 오류가 없다.

둘 다 Device Tree 를 바꾸는 줄이라 재부팅해야 반영된다.

@@ eio-d1-pdf-p16-1
슬라이드 p.16 의 raspi-config 명령이다. 0 은 켜기, 1 은 끄기다. I2C · SPI · UART 하드웨어는 켜고, 시리얼 로그인 콘솔은 끈다. 같은 슬라이드에서 config.txt `[all]` 아래에 `dtoverlay=pwm-2chan` 과 `dtoverlay=disable-bt` 를 추가하고, `systemctl disable hciuart` 후 재부팅한다. 줄 끝 주석은 overlay 이름으로 읽혀 적용되지 않으니 별도 줄에 쓴다.

@@ eio-d1-sec6-1
C 개발 도구를 설치하고 버전을 확인한다.
- `build-essential`: gcc · make 등 빌드 도구 묶음.
- `gpiod`: gpiodetect · gpioinfo · gpioset 같은 명령줄 도구.
- `libgpiod-dev`: C 에서 쓰는 헤더(gpiod.h)와 라이브러리.
- `i2c-tools`: i2cdetect 등 I2C 확인 도구 (Day 4).
- `gcc --version | head -1`: 컴파일러 버전 첫 줄만 본다.
- `pkg-config --modversion libgpiod`: 설치된 libgpiod 버전. 반드시 2.x 여야 한다. 1.x 와 2.x 는 C API 가 완전히 달라 인터넷 예제의 대부분(1.x)은 컴파일되지 않는다.
- `gpiodetect --version`: 명령줄 도구도 v2 인지 본다.

@@ eio-d1-sec6-2
`ls /usr/include/gpiod.h` 로 헤더가 설치됐는지 확인하고, `pkg-config --cflags --libs libgpiod` 로 gcc 에 넘길 옵션을 본다. 결과는 `-lgpiod` 로, 빌드할 때 이 옵션을 붙여 libgpiod 와 링크한다.

@@ eio-d1-sec6-3
하드웨어 장치 파일의 권한과 내 그룹을 확인한다. `ls -l` 맨 앞 `c` 는 문자 장치, `rw-rw----` 는 소유자(root)와 그룹만 읽고 쓸 수 있다는 뜻이다. 그룹은 gpiochip0 = gpio, i2c-1 = i2c, spidev0.0 = spi, ttyAMA0 = dialout 이고, `254, 0` 같은 두 숫자는 드라이버를 가리키는 major · minor 번호다. `groups` 출력에 gpio · i2c · spi · dialout 이 모두 있으면 sudo 없이 하드웨어를 다룰 수 있다.

@@ eio-d1-sec6-5
현재 사용자($USER)를 gpio · i2c · spi · dialout 그룹에 추가한다. `-aG` 의 `-a` 는 기존 그룹을 지우지 않고 덧붙이라는 뜻으로, 빠뜨리면 sudo 그룹에서까지 빠진다. 그룹 변경은 다시 로그인해야 반영된다. 이 과목의 프로그램은 sudo 로 실행하지 않는 것이 원칙이다. 하드웨어 프로그램을 root 로 돌리면 버그 하나가 시스템 전체를 망가뜨린다.

@@ eio-d1-sec6-6
실습 폴더 ~/eio/day1 을 만든다. `-p` 는 중간 폴더(~/eio)가 없으면 함께 만들고, 이미 있어도 오류를 내지 않는다. 그다음 FileZilla 에서 프로토콜 SFTP, 호스트 rpi-07.local, 포트 22, 사용자 pi 로 접속해 Windows 의 src 폴더를 /home/pi/eio/day1/ 로 끌어다 놓는다.

@@ eio-d1-sec6-7
Day 1~5 가 함께 쓰는 Makefile 이다.
- `CC = gcc`, `CFLAGS = -Wall -Wextra -O2 -g`: 경고를 모두 켜고, 최적화하고, 디버그 정보를 넣는다.
- `LDLIBS = $(shell pkg-config --libs libgpiod …) -lpthread`: libgpiod 링크 옵션(-lgpiod)을 pkg-config 로 찾아 넣고, 스레드 라이브러리도 링크한다. `2>/dev/null` 은 pkg-config 오류 메시지를 숨긴다.
- `SRCS = $(wildcard *.c)`, `BINS = $(SRCS:.c=)`: 폴더의 .c 파일 전부와, 거기서 .c 를 뺀 실행 파일 이름 목록.
- `all: $(BINS)`: `make` 만 치면 모든 예제를 빌드한다.
- `%: %.c` 규칙: `make 01_board_info` 처럼 이름 하나를 주면 그 .c 만 빌드한다. `$@` 는 만들 파일, `$<` 는 첫 재료(.c)다. 명령 줄은 반드시 탭으로 시작한다.
- `clean`: 만든 실행 파일을 지운다. `.PHONY` 는 all · clean 이 파일 이름이 아니라는 표시다.

@@ eio-d1-sec6-8
첫 C 예제로, Linux 에서는 보드 정보도 파일로 읽는다는 것을 보여 준다.
- `read_line()`: 파일을 열어 `fgets` 로 첫 줄을 읽고, `strcspn` 으로 찾은 줄 끝 '\n' 자리를 '\0' 으로 바꿔 지운다. 실패하면 -1 을 돌려준다.
- `/proc/device-tree/model`: 5교시의 Device Tree 를 커널이 파일로 보여 주는 것으로, 보드 모델 문자열이 들어 있다. Pi 가 아니면 읽기에 실패한다.
- `uname(&u)`: 커널 이름 · 릴리스 · 아키텍처를 구조체에 채우는 시스템 콜이다.
- `sysconf(_SC_NPROCESSORS_ONLN)`: 지금 켜져 있는 CPU 코어 수.
- `/sys/class/thermal/thermal_zone0/temp`: thermal 드라이버가 SoC 온도를 밀리도 정수(예: 46712)로 내놓는다. `atoi(buf) / 1000.0` 으로 실수 나눗셈을 해 46.7 °C 로 바꾼다.
- `access(path, F_OK)` 로 파일이 있는지, `access(path, R_OK | W_OK)` 로 실제로 열지 않고 내 권한으로 읽고 쓸 수 있는지 검사한다. 권한이 없으면 gpio 그룹을 확인하라고 알려 준다.

@@ eio-d1-sec6-9
예제 01 을 빌드하고 실행한다. `make 01_board_info` 는 공통 Makefile 의 `%: %.c` 규칙으로 01_board_info.c 만 컴파일하고, `./01_board_info` 로 현재 폴더의 실행 파일을 돌린다. 출력에는 보드 모델(Raspberry Pi 4 Model B Rev 1.5), 커널(Linux 6.12… aarch64), CPU 코어 4, SoC 온도, /dev/gpiochip0 읽기 · 쓰기 가능 여부가 나온다. 커널 버전과 온도 숫자는 보드마다 다를 수 있다.

@@ eio-d1-sec6-11
빈칸 6-1 의 정답이다.
- 빈칸 ① `thermal`: 온도 파일은 /sys/class/thermal/thermal_zone0/temp 에 있다.
- 빈칸 ② `1000.0`: 값이 밀리도 정수이므로 1000.0 으로 나눠야 소수점이 살아난다. 1000 으로 나누면 정수 나눗셈이 되어 46.7 이 46.0 으로 나온다.
- 빈칸 ③ `uname`: 커널 이름 · 릴리스 · 아키텍처(`u.machine` = aarch64)를 구조체에 채우는 시스템 콜이다.
- 빈칸 ④ `access`: 파일을 실제로 열지 않고 읽기 · 쓰기 권한만 검사한다. 0 이면 권한이 있다.

@@ eio-d1-pdf-p19-1
슬라이드 p.19 의 개발 도구 설치 명령이다. build-essential 은 gcc · make, gpiod 는 gpioset · gpioinfo · gpiomon 명령, libgpiod-dev 는 C 헤더 gpiod.h(Day 2~5), i2c-tools 는 i2cdetect(Day 4)를 준다. `pkg-config --modversion libgpiod` 가 2.x(예: 2.2.1)여야 한다. v1 과 v2 는 C API 가 완전히 달라 인터넷의 v1 예제(gpiod_line_request_output …)는 컴파일되지 않는다.

@@ eio-d1-pdf-p19-2
슬라이드 p.19 의 공통 Makefile 핵심 두 줄이다. `LDLIBS` 는 pkg-config 로 찾은 libgpiod 링크 옵션과 `-lpthread` 를 담는다. `%: %.c` 규칙은 `make 이름` 으로 같은 이름의 .c 하나를 빌드하며, `$@` 는 만들 실행 파일, `$<` 는 재료 .c 파일이다. 명령 줄 앞은 반드시 [탭] 이어야 하고 스페이스면 "missing separator" 오류가 난다.

@@ eio-d1-sec7-1
드라이버가 장치를 잡은 기록과 장치 종류를 본다. `dmesg` 는 커널 로그이고, `grep -iE "gpio|pwm|spi|i2c|ttyAMA"` 는 대소문자 구분 없이(-i) 여러 낱말 중 하나(-E 확장 정규식)가 들어간 줄만 고른다. `ls /sys/class/` 는 커널이 분류한 장치 종류(gpio, pwm, thermal …)를 보여 준다. Linux 에서는 드라이버만 레지스터를 만지고, 내 프로그램은 open · read · write · ioctl 로 드라이버에게 부탁한다.

@@ eio-d1-sec7-2
GPIO 칩과 라인 상태를 본다. `gpiodetect` 는 칩 목록을 출력한다. gpiochip0(pinctrl-bcm2711, 58 lines)가 40핀 헤더의 GPIO 를 가진 칩이고, 라인 번호(offset) = BCM 번호다. `gpioinfo -c gpiochip0 | head -20` 은 앞 20줄의 라인별 이름 · 방향 · 사용자를 보여 준다. GPIO7 · 8 처럼 `consumer="spi0 CS0"` 가 붙은 라인은 이미 spidev 가 쓰는 중이라 내 프로그램이 요청하면 "Device or resource busy" 로 실패한다. 라인 이름("GPIO17")은 Device Tree 가 붙인 것이다.

@@ eio-d1-sec7-4
gpioset 으로 GPIO17 의 LED 를 켜고 끈다.
- `gpioset -c gpiochip0 17=1`: 칩 gpiochip0 의 라인 17 을 1(High)로 만든다. libgpiod v2 의 gpioset 은 라인을 쥔 채 끝나지 않고 기다리며, Ctrl+C 를 누르면 라인이 해제된다.
- `-t 500ms`: 0.5초마다 값을 뒤집어 깜빡인다(Ctrl+C 로 종료).
- `gpioset GPIO17=1`: 칩 대신 라인 이름으로 지정한다.

프로그램이 끝나면 fd 가 닫혀 커널이 라인을 해제하므로 그 뒤 핀 상태는 보장되지 않는다. 핀을 계속 쥐려면 프로세스가 살아 있어야 한다.

@@ eio-d1-sec7-5
두 프로세스가 같은 라인을 요청하는 실험이다. 창 1 의 gpioset 이 GPIO17 을 쥐고 있는 동안, 창 2 에서 `gpioinfo -c gpiochip0 17` 을 보면 `consumer="gpioset"` 이 보인다. 창 2 에서 같은 라인을 또 요청하면 "Device or resource busy" 로 실패한다. 창 1 을 Ctrl+C 로 끝낸 뒤에는 성공한다. Linux 에서는 먼저 요청한 프로세스가 라인을 소유한다.

@@ eio-d1-sec7-7
GPIO8 은 5교시에 켠 SPI 의 CS0 로 spi0 드라이버가 쥐고 있어 gpioset 요청이 busy 로 실패한다. 드라이버도 라인의 소유자이므로 버스 핀은 일반 GPIO 로 쓰지 않는다.

@@ eio-d1-sec7-8
빈칸 7-1 의 정답이다.
- 빈칸 ① `gpiodetect`: 칩 이름 · 드라이버 · 라인 수를 보여 준다.
- 빈칸 ② `17`: libgpiod v2 명령은 `-c 칩` 다음에 offset(= BCM 번호)을 쓴다.
- 빈칸 ③ `17=1`: 라인 17 을 1(High)로 만든다.
- 빈칸 ④ `-t`: toggle 주기를 주면 그 간격으로 값을 뒤집으며 계속 실행된다.

모두 Ctrl+C 로 끝내면 라인이 해제된다.

@@ eio-d1-pdf-p22-1
슬라이드 p.22 의 창 2 명령이다. 창 1 의 gpioset 이 GPIO17 을 쥐고 있으면 gpioinfo 에 `consumer="gpioset"` 이 보이고, 같은 라인을 또 요청하면 EBUSY("Device or resource busy")다. 창 1 을 Ctrl+C 나 kill -9 로 끝내면 fd 가 닫혀 커널이 라인을 정리한다. GPIO8 처럼 spi0 CS0 가 쥔 핀도 busy 이므로 버스 핀은 일반 GPIO 로 쓰지 않는다.

@@ eio-d1-sec8-1
gpioget 으로 GPIO5 버튼 값을 한 번 읽는다.
- `-b pull-up`: 내부 풀업을 켠다. 안 누르면 High 라 `"5"=active`, 누르면 GND 로 떨어져 `"5"=inactive` 다.
- `--numeric`: active/inactive 대신 1 / 0 숫자로만 출력한다.
- bias 없이 읽으면 버튼을 안 눌렀을 때 핀이 떠 있어(floating) 값이 0 과 1 을 오간다. 입력 핀에는 항상 pull-up 또는 pull-down 이 필요하다.

@@ eio-d1-sec8-2
gpiomon 으로 버튼의 엣지(값이 바뀌는 순간)를 기다린다.
- `-e falling`: High → Low(누르는 순간)만 받는다. 누를 때마다 한 줄이 찍힌다.
- `-e both -p 10ms`: 누름과 뗌을 모두 받고, 10ms 안의 떨림은 커널이 걸러 준다(디바운스).
- `-n 3`: 이벤트 3개를 받으면 끝난다.

출력 맨 앞 숫자는 커널이 엣지를 받은 시각(초.나노초)이다. 한 번 눌렀는데 몇 ms 차이로 여러 줄이 찍히면 접점이 떨리는 바운싱이다.

- `INPUT_PULLUP`: MCU(Arduino) 의 내부 풀업 입력 모드. Pi 의 `-b pull-up` 과 같다.
- `active`: pull-up 버튼을 안 눌렀을 때 gpioget 이 보여 주는 값(1).
- `inactive`: 버튼을 눌렀을 때의 값(0).
- `-p 10ms`: 10ms 안의 접점 떨림을 커널이 걸러 주는 디바운스 옵션.
- `top`: CPU 사용률을 보는 명령. gpiomon 이 기다리는 동안 CPU 를 거의 쓰지 않음(0.0%)을 확인한다.
- `gpiomon`: 엣지 이벤트를 기다리는 명령.
- `poll()`: Day 2 에 gpiomon 과 같은 기다리기를 C 로 하는 시스템 콜.
- `gpioset`: 라인에 값을 쓰는 명령. 셸 맛보기에서 누를 때마다 새로 실행된다.
- `[ OK ]`: check_env.sh 통과 표시. 모두 OK 여야 Day 2 를 시작한다.
- `src/check_env.sh`: Day 1 미니 프로젝트 점검 스크립트.
- `[FAIL]`: 실패 표시. 그 줄에 고치는 명령이 함께 적혀 있다.
- `bash check_env.sh && echo READY`: 스크립트가 종료 코드 0 으로 끝날 때만 READY 를 출력한다(도전 과제).
- `timeout 2 gpioset -c gpiochip0 -t 200ms 17=1`: LED 를 0.2초 간격으로 2초 동안 깜빡인 뒤 끝낸다(도전 과제).
- `gpiomon … -n 1`: 이벤트 하나를 받으면 끝나는 gpiomon. 버튼 점검 항목에 쓴다.
- `timeout 5`: 뒤 명령을 5초 안에 끝나지 않으면 강제로 끝낸다. 5초 안에 버튼이 눌리면 OK.
- `-b`: bias(내부 저항) 옵션.
- `-p`: debounce period 옵션.
- `-n`: 받을 이벤트 수 옵션.
- `/etc/os-release`: OS 이름 · 버전 변수가 담긴 파일.
- `VERSION_CODENAME`: os-release 의 버전 이름 변수(trixie).
- `PRETTY_NAME`: os-release 의 사람이 읽는 OS 이름 변수.
- `-e`: test 에서 종류와 상관없이 경로가 있는지 본다.
- `-f`: test 에서 일반 파일인지 본다. 장치 파일에는 항상 거짓이다.
- `/dev/i2c-1`: I2C 버스 1번 장치 파일.
- `pkg-config --modversion`: 설치된 개발 패키지 버전을 출력한다.
- `/dev/gpiochip0`: GPIO 칩 장치 파일.

- `/dev/ttyAMA0`: PL011 UART 장치 파일.
