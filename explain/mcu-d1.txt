Day 1 개요(사용법 · 핀 배정 · 따라 꽂기)에 나온 기호와 브레드보드 위치다.
- `// →`: 예제 주석에서 `// →` 뒤에 적힌 것이 시리얼 모니터에 나와야 하는 기대 출력이다.
- `____`: 빈칸 채우기 문제의 빈칸 표시. 이 자리를 채워서 업로드한다.
- `enum`: C 과정에서 배운 열거형. 오늘 신호등 · 게임 상태를 이름 붙은 상수로 표현할 때 쓴다.
- `esp32`: 보드 매니저에서 설치하는 보드 패키지 이름(esp32 by Espressif), 보드 메뉴의 esp32 → ESP32 Dev Module.
- `COMx`: Windows 에서 보드를 꽂으면 생기는 시리얼 포트 이름(COM3, COM5 …). CP2102 칩이 만들어 주는 포트다.
- `/dev/ttyUSB0`: Linux 에서 같은 보드가 잡히는 시리얼 장치 파일 이름.
- `e4–f4`: 빨강 LED 용 220Ω 저항을 가운데 홈을 건너 e4 와 f4 에 꽂는다.
- `e8–f8`: 노랑 LED 용 저항 자리.
- `e12–f12`: 초록 LED 용 저항 자리.
- `g4 · g5`: 빨강 LED 자리. 긴 다리(+)가 g4(저항 쪽), 짧은 다리(−)가 g5.
- `g8 · g9`: 노랑 LED 자리 (+ 가 g8).
- `g12 · g13`: 초록 LED 자리 (+ 가 g12).
- `e18–f18`: 기울기 센서(Ball Tilt Sensor) 자리. 방향이 없다.
- `e23 · e25 · f23 · f25`: 버튼의 네 다리가 가운데 홈을 건너 꽂히는 자리. 대각선 두 다리(a23 쪽 신호, j25 쪽 GND)를 쓴다.
- `e31 (+) – f31`: Active 부저(뒷면이 막힌 부저) 자리, + 표시가 위쪽(e31).
- `e37 (+) – f37`: Passive 부저(뒷면에 기판이 보이는 부저) 자리, + 가 e37.
- `j5 · j9 · j13 · j18 · j25 · j31 · j37`: 각 부품의 − 쪽 열을 짧은 점퍼선으로 바로 아래 파란 − 레일(GND)에 잇는 자리.

@@ mcu-d1-sec1-1
핀 번호를 받아 그 핀을 출력으로 써도 안전한지(1) 아닌지(0) 판단하는 함수다. 1교시 핀 분류표의 규칙을 그대로 코드로 옮겼다.
- `in_list()` 는 배열 `list` 의 앞 `n` 개 중에 `pin` 이 있으면 1 을 돌려준다. 배열은 함수에 넘기면 포인터(`const int *list`)가 되므로 길이 `n` 을 따로 넘긴다 (C 과정 Day 2 내용).
- 빈칸 ① `34`: GPIO 34~39 는 입력 전용이라 출력이 안 된다.
- 빈칸 ② `5`: STRAP_PINS 배열의 원소가 {0, 2, 5, 12, 15} 다섯 개이므로 길이 5 를 넘긴다. 스트래핑 핀은 부팅 순간 전압으로 동작 모드가 정해져 피한다.
- 빈칸 ③ `3`: GPIO 1(TX) · 3(RX) 은 UART0 이라 업로드와 시리얼 모니터가 쓰고 있다.
- Flash 핀 6~11 도 0 을 돌려준다. 그 밖의 핀만 1(OK).
- 실행하면 25 → OK, 34(입력 전용) · 9(Flash) · 12(Strapping) → NO, 4 → OK 가 나온다.

@@ mcu-d1-sec1-t1
ESP32 개발 보드 위의 부품과 역할이다.
- ESP-32U 모듈 안에 ESP32 칩(Xtensa LX6 듀얼코어 240MHz, SRAM 520KB, Wi-Fi · BT)과 4MB Flash 가 들어 있다.
- CP2102 는 USB ↔ UART 변환 칩이다. PC 에 보이는 COMx 포트가 이 칩이고, `Serial.printf` 출력은 UART → CP2102 → USB → PC 경로로 나간다.
- 레귤레이터는 USB 5V 를 3.3V 로 낮춘다. EN 버튼은 리셋, Boot 버튼을 누른 채 리셋하면 GPIO 0 이 LOW 가 되어 다운로드(업로드) 모드로 들어간다.
- PC 의 C 프로그램은 OS 위에서 돌지만, 여기서는 OS 없이 이 칩 하나에서 프로그램이 돈다.

@@ mcu-d1-sec1-t2
ESP32 핀을 용도별로 나눈 표로, Day 1~4 내내 핀을 고를 때 기준이 된다.
- 일반 GPIO(4, 13, 14, 16~19, 21~23, 25~27, 32, 33)만 출력용으로 고른다.
- 34 · 35 · 36(VP) · 39(VN) 은 입력 전용이고 내부 풀업이 없다. 아날로그 센서용으로 Day 2 에 쓴다.
- Strapping 핀(0, 2, 5, 12, 15)은 부팅 순간 전압으로 동작 모드가 정해진다. 특히 12 는 피한다.
- Flash 핀(6~11, 보드 표기 CLK · D0~D3 · CMD)은 절대 쓰지 않는다. 쓰면 부팅이 안 된다.
- UART0(1 TX, 3 RX)은 업로드와 시리얼 모니터가 사용 중이다. 3V3 은 출력 전원, 5V 는 USB 전원이 그대로 나온다.

@@ mcu-d1-sec1-p1-2
ESP32 보드 구조를 확인하는 괄호 넣기다.
1. ESP32 는 Xtensa LX6 듀얼코어, 최대 240MHz 로 동작한다 (보드 부품 표의 ESP-32U 모듈 설명).
2. 보드 위 정사각형 칩 CP2102 가 USB ↔ UART 를 변환해 PC 에 COM 포트로 보인다.
3. 34~39 번은 입력 전용 핀이고 내부 풀업이 없으므로 버튼에 INPUT_PULLUP 을 쓸 수 없다.
4. CLK · D0~D3 · CMD(GPIO 6~11)는 내부 Flash 에 연결되어 있어 건드리면 부팅이 안 된다.
5. ESP32 GPIO 는 3.3V 논리다. 5V 신호를 바로 넣으면 안 되는 이유다.

@@ mcu-d1-sec1-inline
1교시 본문에 나온 코드 조각이다.
- `COMx`: PC 에서 보이는 보드의 시리얼 포트 이름. CP2102 칩이 만들어 준다.

@@ mcu-d1-sec2-8
'컴파일된 바이너리 내보내기(Alt+Ctrl+S)' 를 하면 스케치 폴더 안 build\ 에 생기는 빌드 결과물이다.
- `.ino.bin`: 실제 앱 이미지. Flash 주소 0x10000 에 쓰인다.
- `.bootloader.bin`(0x1000)과 `.partitions.bin`(0x8000): 부트로더와 Flash 를 어떻게 나눠 쓸지 적은 파티션 표.

- `.map`: 함수 · 변수가 메모리 어디에 놓였는지 보여 주는 지도.
예제 2-2 의 빌드 단계(전처리 → 컴파일 → 링크 → .bin 변환)가 실제 파일로 남은 것이다.

@@ mcu-d1-sec2-9

@@ mcu-d1-sec2-10
첫 스케치. 칩 정보를 한 번 출력하고, 1초마다 부팅 후 경과 시간을 출력한다.
- Arduino 에는 `main()` 이 없고 `setup()`(한 번)과 `loop()`(계속 반복)를 쓴다.
- `Serial.begin(115200)` 으로 시리얼 속도를 정한다. PC 의 시리얼 모니터도 115200 이어야 글자가 깨지지 않는다.
- `printf` 대신 `Serial.printf` 를 쓰며 서식 지정자(%d, %s, %lu)는 C 와 같다.
- `ESP.getChipModel()` · `getChipCores()`(2) · `getCpuFreqMHz()`(240) · `getFlashChipSize()`(4194304 = 4MB) · `getFreeHeap()` 으로 칩 정보를 읽는다.
- `loop()` 의 `millis()` 는 부팅 후 경과 시간(ms), `delay(1000)` 은 1초 멈춤이다.

@@ mcu-d1-sec2-t10
'자세한 출력' 을 켠 빌드 로그에서 찾을 6단계와 C 과정(gcc)의 대응이다.
- 1 전처리: .ino 가 .ino.cpp 로 바뀌며 함수 원형이 자동으로 추가된다.
- 2 컴파일: `xtensa-esp32-elf-g++ -c` 로 .o 를 만든다 (gcc -c 와 같음).
- 3 링크: core 라이브러리와 묶어 .elf 를 만든다.
- 4 이미지 변환: esptool elf2image 로 .bin 을 만든다 (PC 에는 없는 단계).
- 5 크기 보고: Sketch uses … bytes (size 명령과 같음).
- 6 업로드: esptool write_flash 로 bootloader(0x1000) · partitions(0x8000) · boot_app0(0xe000) · 앱(0x10000)을 Flash 에 쓴다.
MCU 에는 OS 가 없어 Flash 의 정해진 주소에 이미지를 써 두고, 전원이 켜지면 ROM → bootloader → 파티션 표 → 앱 순서로 시작한다.

@@ mcu-d1-sec2-p2-2
빌드 · 업로드 과정을 확인하는 괄호 넣기다.
1. ESP32 의 CPU 가 Xtensa 구조라서 컴파일러 이름이 xtensa-esp32-elf-g++ 다.
2. 링크하면 .elf 가 나오고(디버그 정보 포함), esptool elf2image 가 이것을 Flash 에 쓸 .bin 으로 바꾼다.
3. 앱 이미지는 0x10000 에 쓰인다 (0x1000 bootloader, 0x8000 파티션 표).
4. 코어의 app_main 이 만든 FreeRTOS 태스크 loopTask 가 setup() 을 한 번, loop() 를 계속 부른다.
5. Boot 버튼을 누르고 있으면 GPIO 0 이 LOW 가 되어 다운로드 모드로 들어간다. EN 은 리셋 버튼이다.

@@ mcu-d1-pdf-p17-1
슬라이드에 실린 Arduino-ESP32 코어 내부(간략화)다. `main()` 은 사라진 것이 아니라 코어 안의 `app_main()` 으로 숨어 있다. `app_main()` 이 `initArduino()` 후 `xTaskCreatePinnedToCore()` 로 loopTask 태스크(스택 8192, 우선순위 1, core 1)를 만들고, loopTask 가 `setup()` 을 한 번, `for (;;) loop();` 로 loop 를 무한히 부른다. setup/loop 는 FreeRTOS 태스크 하나 안의 평범한 함수다.

- `.ino`: 스케치 소스 (빌드 과정의 시작).
- `.cpp`: 전처리로 만들어지는 C++ 파일.
- `.elf`: 링크 결과물.
- `.bin`: Flash 0x10000 에 쓰는 이미지.
- `setup`: loopTask 안에서 한 번 불리는 함수.
- `loop`: loopTask 안에서 반복 호출되는 함수.
- `loopTask`: setup/loop 를 부르는 FreeRTOS 태스크 (D1-2 정리).
- `static`: 유지할 지역 변수에 붙이는 키워드 (D1-3 정리).
- `W1TS`: 한 핀만 켜는 레지스터 (D1-4 정리).
- `W1TC`: 한 핀만 끄는 레지스터.
- `1UL << pin`: 레지스터에 쓸 그 핀의 비트 마스크.
- `INPUT_PULLUP`: 버튼 입력 모드 (D1-5 정리: INPUT_PULLUP + 논블로킹 디바운스).
- `IRAM_ATTR`: ISR 에 붙이는 표시. ISR 은 짧게, 표시만 (D1-6 정리).
- `volatile`: ISR 과 공유하는 변수에 붙인다. 읽고-바꾸기는 임계 구역으로.
- `anim/worksheet.html`: Day 1 개념 워크시트 페이지.
