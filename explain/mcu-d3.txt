@@ mcu-d3-sec1-1
7-Segment 의 세그먼트 이름과 비트 배치 그림이다. 위에서 시계 방향으로 a · b · c · d · e · f, 가운데가 g, 점이 dp 다. 오늘 규칙은 a = bit0 … g = bit6, dp = bit7. 그래서 "0" 은 a~f 가 켜지고 g · dp 가 꺼져 0011 1111 = 0x3F 다. 1자리는 COM 에 220Ω 하나만 두어서, 켜진 세그먼트가 많을수록 전류를 나눠 써 "8" 이 "1" 보다 조금 어둡다.

@@ mcu-d3-sec1-2
세그먼트를 하나씩 켜서 내 7-Segment 가 공통 음극(CC)인지 공통 양극(CA)인지 확인한다. 세그먼트 핀 a~dp 를 GPIO 13 · 14 · 27 · 26 · 25 · 33 · 32 · 23 에 잇고, 모두 LOW 로 끈 뒤 하나만 HIGH 로 켠다. CC(COM 이 GND)면 하나씩 순서대로 켜지고, CA(COM 이 3V3)면 하나만 꺼지고 나머지가 켜진다(또는 COM 이 GND 라 전부 꺼짐 → COM 을 3V3 으로). 제품 번호 끝 …AS 는 CC, …BS 는 CA 인 경우가 많지만 직접 확인이 가장 확실하다.

@@ mcu-d3-sec1-3
숫자 0~9 모양을 1바이트 비트맵 배열 `DIGITS[]` 로 두고 차례로 표시한다.
- 각 바이트의 비트 i 가 세그먼트 i(a = bit0 … dp = bit7)의 켜짐을 뜻한다. 예: 0 = 0x3F, 1 = 0x06(b · c), 8 = 0x7F.
- `seg_show()` 는 `(pattern >> i) & 1` 로 i번째 비트를 꺼내 그 세그먼트 핀에 쓴다 (Day 1 의 비트 검사와 같다).
- CA 부품이면 `pattern = ~pattern` 으로 뒤집는다 (LOW 가 켜짐).
- 마지막에 `0x80` 으로 점(dp)만 켠다. 숫자 모양이 코드가 아니라 데이터(표)다.

@@ mcu-d3-sec1-4
16진수 한 자리(0~F)를 표시하고 원하면 점도 켠다. HEX_FONT 에 0~9 와 A · b · C · d · E · F 모양이 들어 있다.
- 빈칸 ① `>>`: `(pattern >> i) & 1` 로 i번째 비트를 꺼낸다.
- 빈칸 ② `0x0F`: `v & 0x0F` 로 하위 4비트만 남겨 0~15 로 만든다 (배열 밖 접근 방지).
- 빈칸 ③ `|=`: `p |= 0x80` 으로 다른 비트는 건드리지 않고 dp(bit7)만 켠다 (Day 1 의 W1TS 와 같은 생각).

@@ mcu-d3-sec1-t1
7-Segment 함정 표다. CA 부품인데 COM 을 GND 에 달면 아무것도 안 켜지므로 COM 을 3V3 으로 옮기고 COMMON_ANODE = true 로 한다. a 를 bit7 로 착각하면 엉뚱한 모양이 나온다 (오늘 규칙 a = bit0, dp = bit7). COM 두 핀은 속에서 이어진 제품이 많지만 둘 다 연결하는 것이 원칙이다. 저항 없이 COM 을 GND 에 직결하면 과전류로 부품 · 핀이 손상될 수 있다.

@@ mcu-d3-sec1-p1-2
7-Segment 비트맵을 확인하는 괄호 넣기다.
1. 오늘 규칙은 a = bit0, dp = bit7.
2. 숫자 0 은 a~f 켜짐 = 0011 1111 = 0x3F.
3. 공통 양극(CA)은 COM 을 3V3 에 두고 세그먼트에 LOW 를 줘야 전류가 흘러 켜진다.
4. 비트를 모두 뒤집는 연산자는 `~`(NOT).

@@ mcu-d3-pdf-p6-1
슬라이드의 `seg_show()` 다. 공통 양극이면 `p = ~p` 로 비트맵을 뒤집고, 8개 세그먼트 핀에 `(p >> i) & 1` 로 i번째 비트를 하나씩 쓴다. 슬라이드 표: 0 = 0x3F, 1 = 0x06, 2 = 0x5B, 8 = 0x7F. CC 는 COM 을 GND(220Ω), 켤 때 HIGH / CA 는 COM 을 3V3, 켤 때 LOW.

@@ mcu-d3-sec1-inline
1교시(7-Segment) 본문에 나온 코드 조각이다.

- `seg_test.ino`: 예제 1-1 세그먼트 하나씩 켜 보기 스케치.
- `…AS`: 제품 번호 끝이 AS 면 대개 공통 음극(CC).

@@ mcu-d3-sec2-1
74HC595 시프트 레지스터에 1바이트를 직접 밀어 넣는다. 선 3개(DS 데이터 23, SH 시프트 클럭 18, ST 래치 19)로 출력 8개(Q0~Q7)를 제어한다.
- `my_shift_out()` 은 MSB(bit7)부터 한 비트씩 DS 에 올리고 SH 를 HIGH → LOW 로 한 번 쳐서 한 칸씩 민다. 8번 밀면 처음 넣은 bit7 은 Q7 까지, 마지막 bit0 은 Q0 에 남는다.
- `write595()` 는 ST(래치)를 LOW 로 두고 밀어 넣은 뒤 HIGH 로 올린다. 래치가 오르는 순간 8개 출력이 동시에 바뀌므로 밀어 넣는 중간 모양은 보이지 않는다.
- loop 는 `1 << i` 로 Q0 → Q7 을 하나씩 켜서 7-Segment 의 a, b, … dp 가 차례로 켜진다.

@@ mcu-d3-sec2-2
595 를 통해 7-Segment 에 숫자 0~9 를 표시한다. 1교시는 GPIO 8개를 썼지만 지금은 3개다. `shiftOut(PIN_DS, PIN_SH, MSBFIRST, data)` 는 my_shift_out 과 같은 일을 하는 Arduino 내장 함수다. 595 의 Q7' 을 다음 595 의 DS 로 이으면 같은 3개 선으로 16, 24 … 개를 제어할 수 있다 (키트에 595 가 1개라 개념만).

@@ mcu-d3-sec2-3
LSB(bit0)를 먼저 보내는 시프트 함수다. 같은 모양이 나오려면 배선에서 Q0 와 Q7 순서가 반대여야 한다.
- 빈칸 ① `0`: i 를 0 부터 7 까지 올리며 bit0 부터 보낸다.
- 빈칸 ② `i`: `(data >> i) & 1` 로 i번째 비트를 DS 에 올린다.
- 빈칸 ③ `HIGH`: 시프트 클럭 SH 를 HIGH → LOW 로 쳐서 한 칸 민다.
- 빈칸 ④ `PIN_ST`: 다 밀어 넣은 뒤 래치를 HIGH 로 올려 출력에 반영한다.
LSB 먼저 보내면 처음 넣은 bit0 이 Q7 까지 밀려간다. `shiftOut(…, LSBFIRST, …)` 와 같다.

@@ mcu-d3-sec2-t1
74HC595 핀 연결과 역할이다.
- 14 DS(SER) → GPIO23: 넣을 비트.
- 11 SH_CP(SRCLK) → GPIO18: 상승 에지마다 한 칸 밀기 (시프트 클럭).
- 12 ST_CP(RCLK) → GPIO19: 상승 에지에 8비트를 출력 핀으로 복사 (래치).
- 13 OE → GND: LOW 면 출력이 켜진다.
- 10 MR → 3V3: LOW 면 전체 지우기라 평소 HIGH 로 고정.
- 15, 1~7 Q0~Q7 → 7-Segment a~dp: 출력.
- 9 Q7' → 비움: 다음 595 의 DS 로 이어 여러 개를 연결할 때 쓴다.

@@ mcu-d3-sec2-t2
74HC595 함정 표다. 래치(ST_CP)를 안 올리면 아무리 보내도 출력이 안 바뀐다. MR 이 떠 있으면 가끔 전부 지워지므로 3V3 에, OE 가 떠 있으면 출력이 깜빡이므로 GND 에 고정한다. 595 를 거꾸로(홈이 오른쪽) 꽂으면 VCC 와 GND 가 뒤바뀌어 뜨거워지니 즉시 USB 를 뺀다. LSBFIRST 로 보내면 비트 순서가 뒤집혀 모양이 거울처럼 바뀐다.

@@ mcu-d3-sec2-p2-2
74HC595 를 확인하는 괄호 넣기다.
1. 시프트 클럭 SH_CP(SRCLK)가 올라갈 때마다 비트가 한 칸 밀린다.
2. 래치 ST_CP(RCLK)가 올라가면 밀어 넣은 8비트가 출력 핀으로 한 번에 복사된다.
3. OE 는 LOW 여야 출력이 켜지므로 GND, MR 은 LOW 면 지워지므로 3V3.
4. 앞 595 의 Q7'(직렬 출력)을 다음 595 의 DS 에 이어 여러 개를 연결한다.

@@ mcu-d3-pdf-p8-1
슬라이드의 74HC595 출력 코드다. `my_shift_out()` 은 MSB 부터 비트를 DS 에 올리고 SH 클럭으로 한 칸씩 밀며, `write595()` 는 래치 ST 를 LOW 로 둔 채 밀어 넣고 HIGH 로 올려 8개 출력을 한 번에 바꾼다. Arduino 의 `shiftOut(DS, SH, MSBFIRST, d)` 와 같다. 래치를 올리기 전에는 출력이 바뀌지 않는다.

@@ mcu-d3-sec3-1
4자리 7-Segment 를 loop 로 멀티플렉싱한다. 595 는 세그먼트 모양을, GPIO 25 · 26 · 27 · 14 는 자리(D1~D4)의 공통 단자를 맡는다.
- `show_digit(k)` 는 네 자리를 모두 끄고(CC 는 HIGH = 꺼짐) → 595 로 k번째 모양을 보내고 → k번째 자리만 LOW 로 켠다.
- 한 자리 3 ms × 4 = 12 ms, 약 83Hz 로 돌리면 사람 눈(약 50Hz 이상은 깜빡임을 못 느낌)에는 "1234" 가 동시에 보인다.
- 한계: loop 에서 delay(100) 같은 다른 일을 하면 갱신이 멈춰 한 자리만 오래 켜지고 깜빡인다. 다음 예제에서 타이머로 해결한다.

@@ mcu-d3-sec3-2
하드웨어 타이머 인터럽트로 화면 갱신을 loop 와 분리한다. loop 가 delay(100) 으로 쉬어도 화면은 깜빡이지 않는다.
- `timerBegin(1000000)` 은 1MHz 타이머(1틱 = 1µs), `timerAttachInterrupt(timer, &onTimer)` 로 ISR 을 붙이고, `timerAlarm(timer, 2000, true, 0)` 으로 2000µs 마다 반복 호출한다 (core 3.x 방식).
- `onTimer()` 는 지금 자리를 끄고 `cur = (cur + 1) % 4` 로 다음 자리를 골라 모양을 보내고 켠다.
- ISR 규칙은 Day 1 과 같다: `IRAM_ATTR`(ISR 이 부르는 write595 까지), 짧게, 공유 화면 버퍼 `disp[]` 와 `cur` 은 `volatile`.
- `show_number()` 는 `n % 10` 으로 일의 자리를 꺼내고 `n /= 10` 으로 줄이며 오른쪽 자리부터 채운다.
- 인터넷의 `timerBegin(0, 80, true)` 는 2.x 방식이라 컴파일되지 않는다.

@@ mcu-d3-sec3-3
숫자를 자릿수로 나누되 앞자리 0 은 끈다 (예: 42 → " 42").
- 빈칸 ① `0x00`: 모든 세그먼트를 끈 빈칸 모양.
- 빈칸 ② `%`: `n % 10` 은 일의 자리 숫자.
- 빈칸 ③ `/=`: `n /= 10` 으로 한 자리 오른쪽으로 민다 (비트 시프트의 10진수 버전).
`k < 3` 조건 덕분에 숫자가 0 이어도 맨 오른쪽 자리에는 "0" 이 남는다.

@@ mcu-d3-sec3-t1
4자리 멀티플렉싱 함정 표다.
- 자리를 바꾸기 전에 이전 자리를 끄지 않으면 옆 자리에 숫자가 희미하게 겹친다(고스팅). 끄기 → 모양 바꾸기 → 켜기 순서를 지킨다.
- 한 자리에 20 ms 머물면 4자리 80 ms → 12Hz 라 눈에 띄게 깜빡인다.
- ISR 에서 Serial.printf · delay 를 쓰면 느려지거나 리셋된다.

@@ mcu-d3-sec6-1
I2C 버스에 연결된 장치 주소를 모두 찾는 스캐너다.
- `Wire.begin(21, 22)` 로 SDA 21 · SCL 22 를 쓴다.
- 주소 1~126 마다 `Wire.beginTransmission(addr)` → `Wire.endTransmission()` 으로 빈 전송을 해 본다.
- 반환값 0 은 그 주소의 장치가 ACK 로 응답했다는 뜻이다. 2 는 응답 없음(NACK), 그 밖은 버스 오류다.
- 찾은 주소를 `0x%02X` 로 출력한다. PCF8591 이면 0x48 이 나온다.
아무것도 안 나오면 SDA · SCL 이 바뀌었거나 전원이 빠진 것이다. 5교시 병렬 LCD 는 I2C 장치가 아니어서 나오지 않는다.

@@ mcu-d3-sec6-2
라이브러리 없이 Wire 로 PCF8591 의 ADC 채널을 읽는다.
- `Wire.write(0x40 | (ch & 0x03))` 는 제어 바이트다. 0x40 은 bit6(DAC 켜기), 아래 2비트는 채널 번호(0~3)다.

- `Wire.requestFrom(PCF, (uint8_t)2)` 로 2바이트를 요청하고 첫 바이트는 버린다. PCF8591 은 요청을 받는 순간 변환을 시작해서 첫 바이트가 지난번 변환 결과이기 때문이다.
- 두 번째 `Wire.read()` 가 지금 값(0~255, 8비트)이다.
ESP32 ADC(12비트)보다 거칠지만, 핀이 모자랄 때 외부 ADC 로 쓴다.

@@ mcu-d3-sec6-3

- `endTransmission() == 0` 으로 성공 여부를 bool 로 돌려준다.
- loop 는 값을 4 씩 올렸다 내려서 모듈의 Aout LED 를 부드럽게 밝혔다 어둡게 한다.
Day 1 PWM 은 빠르게 켜고 끄는 것이고, DAC 는 진짜 중간 전압이다. LED 는 약 1.8V 아래에서는 안 켜지므로 값이 작을 때는 어둡게 머문다.

@@ mcu-d3-sec6-4

I2C 두 선(21 · 22)과 LCD 여섯 선은 핀이 달라 함께 동작한다.

@@ mcu-d3-sec6-5
`pcf_read` 를 완성하는 빈칸 채우기다.
- 빈칸 ① `addr`: 구조체에 저장한 장치 주소로 전송을 시작한다.
- 빈칸 ② `0x03`: 채널 번호를 아래 2비트(0~3)로 제한하는 마스크.
- 빈칸 ③ `2`: 이전 값 + 지금 값, 2바이트를 요청한다.

@@ mcu-d3-sec6-t1
키트 PCF8591 모듈(Keyestudio) 핀 배치표다.
- 윗줄 Scl · Sda · Vcc · Gnd 는 GPIO22 · GPIO21 · 3V3 · GND 에 연결한다. SCL 이 SDA 보다 왼쪽에 있어 순서에 주의한다.
- 아랫줄 IN0~IN3 은 ADC 입력이다. 오늘은 IN0 에 조도 센서 분압 가운데를 연결한다.

기판의 4.7kΩ I2C 풀업이 Vcc 에 연결되어 있어서 Vcc 를 5V 에 꽂으면 SDA · SCL 이 5V 가 된다. Vcc 는 반드시 3V3 이다.

@@ mcu-d3-sec6-t2
PCF8591 제어 바이트 비트 구성(데이터시트)이다.
- bit7 = 0, bit3 = 0 (고정).
- bit6: DAC 출력 켜기.
- bit5 · 4: 입력 방식 (00 = 단일 입력 4채널).
- bit2: 자동 증가 (읽을 때마다 채널이 넘어감).
- bit1 · 0: 채널 번호.
예: AIN0 읽기 + DAC 켜기 = 0100 0000 = 0x40, AIN2 = 0x42. 코드에서는 `0x40 | (ch & 0x03)` 로 만든다.

@@ mcu-d3-sec6-t3
I2C · PCF8591 함정 표다.
- SDA · SCL 을 바꿔 꽂으면(모듈은 Scl 이 왼쪽) 스캐너가 아무것도 못 찾는다.
- 모듈 Vcc 를 5V 에 꽂으면 기판 풀업 때문에 SDA · SCL 이 5V 가 되어 ESP32 핀이 위험하다 → 3V3.
- `requestFrom(…, 1)` 로 한 바이트만 읽으면 항상 한 박자 늦은 값이다 → 2바이트 읽고 첫 바이트 버림.
- 제어 바이트에 0x40 을 안 넣으면 DAC 가 꺼져 AOUT 이 0V 다.
- 반환값을 검사하지 않으면 선이 빠져도 255 나 이전 값이 나와 고장을 모른다.
- 병렬 LCD 는 I2C 장치가 아니라 스캐너에 안 나오는 것이 정상이다.

@@ mcu-d3-sec6-p6-2
I2C 와 PCF8591 을 확인하는 괄호 넣기다.
1. I2C 는 SDA(데이터) · SCL(클럭) 두 선을 쓰고 장치는 7비트 주소로 구분한다.
2. `Wire.endTransmission()` 반환값 0 = 장치가 ACK 로 응답함.
3. 제어 바이트의 bit6 이 DAC 출력 켜기다 (0x40).
4. 읽은 첫 바이트는 이전(지난번) 변환 결과라서 버린다.

@@ mcu-d3-md-sec6-1

@@ mcu-d3-md-sec6-t2

1. PCF8591 기본 I2C 주소는 0x48 이다.

@@ mcu-d3-sec7-t2
L293D H-브리지의 IN1 · IN2 조합에 따른 모터 동작표다.
- IN1 HIGH · IN2 LOW: 정방향.
- IN1 LOW · IN2 HIGH: 역방향 (모터 양 끝 전압이 반대로 걸린다).

@@ mcu-d3-pdf-p19-1
슬라이드 p.19 의 I2C 스캐너 요약이다. SCL 이 박자를 주고 SDA 에 비트가 실린다. 프레임은 START → 7비트 주소 + R/W → ACK → 데이터 8비트 → ACK → STOP 이고, 장치가 9번째 박자에 SDA 를 LOW 로 당기면 ACK 다.

- 반환값 0 = 성공(ACK), 2 = 주소 NACK(장치 없음), 3 = 데이터 NACK, 그 밖은 버스 오류다.
오늘은 0x48(PCF8591) 하나만 나오면 정상이다.

@@ mcu-d3-pdf-p20-1

@@ mcu-d3-sec7-1
L293D H-브리지로 모터 방향을 바꾼다.
- `PIN_EN`(25)은 속도(Enable), `PIN_IN1`(26) · `PIN_IN2`(27)는 방향이다. 여기서는 EN 을 HIGH 로 두어 최고 속도로 돈다.
- `motor_dir(in1, in2, msg)` 는 두 입력을 쓰고 상태를 출력한다.
- loop 는 정방향(HIGH, LOW) → 정지(LOW, LOW) → 역방향(LOW, HIGH) → 브레이크(HIGH, HIGH) 를 반복한다.
- 반대로 돌리기 전에 먼저 멈춘다. 돌던 모터를 바로 거꾸로 걸면 큰 전류가 흐른다.

@@ mcu-d3-sec7-2
PWM 으로 모터 속도를 조절하고 부드럽게 가속 · 감속한다.
- `motor_set(speed)` 는 속도를 부호 있는 정수 하나(-255~+255)로 받는다. 양수면 IN1, 음수면 IN2 를 HIGH 로 하고, `ledcWrite(PIN_EN, abs(speed))` 로 크기만 PWM 듀티로 낸다. 범위를 넘으면 ±255 로 자른다.
- `ramp_to(int *cur, target)` 은 현재 속도를 포인터로 받아 20 ms 마다 5 씩 목표로 다가가며 갱신한다. 차이가 5 보다 작으면 목표에 맞춘다.
- `ledcAttach(PIN_EN, 20000, 8)` 은 20kHz · 8비트 PWM 이다. 가청 주파수 위라서 윙 하는 소리가 들리지 않는다.
- loop 는 0 → 200 → 0 → -200 → 0 으로 오가며 방향 전환 전에 반드시 0 을 거친다.
듀티가 약 80 이하면 소리만 나고 돌지 않으니 최소 구동값을 실험으로 찾는다.

@@ mcu-d3-sec7-4

@@ mcu-d3-sec7-6

@@ mcu-d3-sec7-t1

- IN1 · IN2(2 · 7번)는 GPIO26 · 27 에 연결해 방향을 정한다.
- OUT1 · OUT2(3 · 6번)에 모터 두 선을 연결한다.
- GND(4 · 5 · 12 · 13번)는 네 개 모두 GND 에 연결한다. 방열도 겸한다.

모터는 수백 mA 가 필요하고(GPIO 는 20mA) 멈출 때 역전압이 생겨서 GPIO 에 직접 연결하지 않는다. L293D 가 작은 신호를 받아 큰 전류를 대신 흘려 주고 보호 다이오드도 들어 있다.

@@ mcu-d3-sec7-t3
릴레이 접점 단자표다. 릴레이는 전자석으로 금속 접점을 움직이는 스위치이고, 접점 쪽은 ESP32 와 전기적으로 분리된 별도 회로다.
- COM: 공통 단자. 전원을 넣는 쪽이다.
- NO(Normally Open): 평소 열림. 코일이 OFF 면 끊기고 ON 이면 COM 과 연결된다.
- NC(Normally Closed): 평소 닫힘. 코일이 OFF 면 COM 과 연결되고 ON 이면 끊긴다.
이 과정에서는 접점에 5V 이하만 연결하고 콘센트 전원(220V)은 절대 연결하지 않는다. 단자 순서는 모듈마다 달라 기판 인쇄로 확인한다.

@@ mcu-d3-sec7-t4

@@ mcu-d3-sec7-t5
L293D 와 릴레이의 역할 차이 정리표다.
- 할 수 있는 것: L293D 는 속도(PWM) · 방향 · 브레이크, 릴레이는 켜기 · 끄기만.
- 전환 속도: L293D 는 초당 수만 번(20kHz PWM), 릴레이는 초당 몇 번이라 PWM 금지.
- 수명: 반도체는 사실상 무제한, 기계 접점은 전환 횟수만큼 닳는다.
- 전기적 분리: L293D 는 GND 를 공통으로 쓰고, 릴레이 접점은 별도 회로다.
- 어울리는 곳: L293D 는 팬 속도 · 바퀴 · 방향 전환, 릴레이는 펌프 · 히터 · 램프 전원과 비상 정지.

@@ mcu-d3-sec7-t6

- 정방향에서 바로 역방향으로 바꾸면 큰 전류로 리셋 · 과열된다 → 멈춘 뒤 반대로.

슬라이드 p.30 의 스테퍼 반스텝 표와 함수다. 28BYJ-48 은 반스텝 약 4096 스텝이 한 바퀴다.
- 표는 phase 0~7 의 SEQ 값(0b0001, 0b0011, 0b0010, 0b0110, 0b0100, 0b1100, 0b1000, 0b1001)을 IN4~IN1 비트로 보여 준다. 코일 하나 → 둘 → 하나 순으로 켜져 반 칸씩 돈다.
- `step_once(dir)` 는 `(phase + dir + 8) % 8` 로 -1 을 7 로 돌리고 `(SEQ[phase] >> i) & 1` 로 코일을 켠다.
- `step_motor(steps, us)` 는 스텝 사이에 `delayMicroseconds(us)`(800µs 이상)를 두고, 멈추면 코일을 꺼 발열을 막는다.
표를 거꾸로 읽으면 반대로 돈다.

8교시(스테퍼 · 종합 과제 · 정리) 본문에 나온 코드 조각이다.

- `ST_CLOSED`: 환기구 닫힘 상태.
- `VENT:CLOSE FAN:0`: 닫힘 상태의 LCD 2행.
- `ST_OPEN`: 환기구 열림 상태.
- `VENT:OPEN FAN:xxx`: 열림 상태의 LCD 2행 (xxx = 팬 속도).
- `smart_vent.ino`: 종합 과제 8-A 스케치.
- `%-5s`: 왼쪽 정렬 5칸 문자열. "OPEN" 과 "CLOSE" 의 길이를 맞춘다.
- `24.6`: 확장 과제에서 7-Segment 에 dp 를 써서 표시할 온도 형식.
- `enum`: 상태를 이름 있는 정수로 정의한다 (`vent_state_t`).
- `(p >> i) & 1`: 비트맵 표에서 i 번째 비트를 꺼낸다 (Day 3 정리 문장).
- `|=`: 비트 켜기.
- `&= ~`: 비트 끄기.
