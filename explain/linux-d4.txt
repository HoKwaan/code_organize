@@ linux-d4-sec1-t1
fd · 열린 파일 · inode 세 단계 표다. fd 테이블은 숫자 → 열린 파일 연결로 프로세스마다 따로 있다(fork 하면 복사). 열린 파일은 현재 위치와 열기 모드를 담고 dup · fork 한 fd 끼리 공유한다. inode 는 크기 · 권한 · 디스크 블록 위치로 같은 파일을 연 모두가 공유한다.

4. dup 한 fd 끼리는 같은 열린 파일을 가리키므로 offset 을 공유한다.

@@ linux-d4-sec3-4
버퍼 단위 복사 루프 빈칸 채우기다.
- 빈칸 ① `read`: 버퍼 크기만큼 읽는다.
- 빈칸 ② `0`: read 가 0 보다 큰 동안 반복한다 (0 은 파일 끝).
- 빈칸 ③ `n`: 요청 크기가 아니라 실제로 읽은 n 만큼만 써야 마지막 조각이 정확하다.
- 빈칸 ④ `fsync`: page cache 의 내용이 디스크에 기록될 때까지 기다린다.

@@ linux-d4-sec3-t1
쓰기 방식별 돌아오는 시점 표다. `write` 는 page cache 에 복사 직후 돌아와 대부분 이것으로 충분하다. `write + fsync` 는 디스크 기록이 끝난 뒤 돌아와 로그 · 설정 저장의 마지막에 쓴다. `open(…, O_SYNC)` 는 매 write 마다 디스크까지 기다려 데이터베이스 저널 등에 쓴다. `sync` 명령은 시스템 전체 dirty 페이지를 기록해 전원 끄기 전에 쓴다.

@@ linux-d4-sec3-p3-2
1. 1 → 4096 바이트면 read · write 횟수가 4096 분의 1 이 된다.
2. write 가 돌아온 직후 데이터는 page cache 에 있다.
3. 디스크까지 기다리려면 `fsync` 를 부른다.
4. 매번 fsync 하면 예제에서 4.4 ms → 233 ms 로 크게 느려진다.

- `sysfs_create_group`: 속성 목록을 한 번에 만드는 함수.
- `kobject_put`: kobject 참조를 놓아 디렉터리와 속성을 정리한다.
- `src/07_sysfs_user.c`: 사용자 프로그램에서 mysysfs 를 읽고 쓰는 예제.
- `kstrtoint`: 커널용 문자열 → 정수 변환 함수.
- `return ret`: 변환 오류를 그대로 돌려 사용자 쪽 write 를 실패시킨다.
- `count`: store 가 받은 바이트 수. 성공하면 이것을 돌려준다.
- `__ATTR`: kobj_attribute 를 만드는 매크로.
- `pr_info(printk)`: pr_info 는 printk 를 정보 수준으로 부르는 매크로.

@@ linux-d4-sec8-1
종합 실습 `sysmon.c` 다. getopt 로 -i 주기 · -n 횟수 · -o CSV · -d 디스크 · -N 네트워크 장치를 받고, 디스크는 sda · vda · nvme0n1 중 있는 것, 네트워크는 lo 가 아닌 첫 장치(`first_net`)를 자동으로 고른다. 주기마다 `cpu_times`(/proc/stat), `mem_used_mb`(/proc/meminfo 의 MemTotal − MemAvailable), 디스크 stat 7번째 값(쓴 섹터), rx_bytes 를 읽어 직전 값과의 차이로 CPU% · 메모리 · 디스크 쓰기 KB/s · 수신 KB/s 를 계산한다. 주기는 Day 2 의 절대 시각 `clock_nanosleep` 으로 맞추고, Ctrl+C(SIGINT)는 g_stop 플래그로 받아 CSV 를 정상 저장하고 끝낸다.

@@ linux-d4-sec8-2
sysmon 실행 명령이다. 1초 주기로 10번 기록해 sys.csv 에 저장하는 동안, 다른 창에서 `stress-ng --cpu 1 --timeout 1` 로 CPU 부하를, `dd … oflag=direct` 로 page cache 를 거치지 않는 100MB 디스크 쓰기를 걸어 값이 바뀌는 것을 본다.

@@ linux-d4-sec8-3
sysmon 기대 출력이다. 2초에 stress-ng 때문에 CPU 80%, 3초에 dd 때문에 디스크 쓰기 102400 KB/s(100MB)가 찍힌다. 같은 내용이 sys.csv 에 time,cpu_pct,mem_used_mb,disk_write_kbps,net_rx_kbps 형식으로 저장된다.

@@ linux-d4-sec8-4
/proc/stat 으로 CPU 사용률을 계산하는 빈칸 채우기다.
- 빈칸 ① `stat`: CPU 시간 누적값이 있는 /proc/stat.
- 빈칸 ② `idle`: 첫 줄의 네 번째 값이 idle 시간.
- 빈칸 ③ `total`: (전체 증가 − idle 증가) / 전체 증가 로 사용률을 구한다.
- 빈칸 ④ `idle`: 다음 계산을 위해 이번 idle 을 보관한다.

@@ linux-d4-sec8-t1
sysmon 이 읽는 값과 계산법 표다. CPU 사용률은 /proc/stat 첫 줄에서 직전 값과의 차이로 (전체 − idle) / 전체, 메모리는 /proc/meminfo 의 MemTotal − MemAvailable, 디스크 쓰기는 /sys/block/sda/stat 7번째 값(쓴 섹터) 차이 × 512 바이트, 네트워크는 rx_bytes 의 직전 값과의 차이다.

@@ linux-d4-src-01_fd.c
예제 01 원본 파일이다. 파일 두 개를 열어 fd 번호(3 · 4)를 확인하고 `/proc/self/fd` 로 fd 목록을 보여 준다. 하나를 닫고 다시 열어 가장 작은 빈 번호 재사용을 보이고, dup · dup2 로 stdout 을 out.txt 로 돌렸다가 되돌린다.

@@ linux-d4-sec8-t2
Day 4 핵심 개념 한 줄 정리표다. fd(번호 → 열린 파일 → inode), dup2(셸 리다이렉션의 정체), inode · 링크(이름은 디렉터리의 한 줄), 버퍼 크기(시스템 콜 횟수가 속도를 정함), fsync(필요한 곳에만), page cache(두 번째 읽기는 RAM, dirty 는 sync 후에야 버림), inotify(저장 끝은 CLOSE_WRITE), sysfs(파일 하나 = 값 하나), 커널 모듈(show · store 콜백을 사용자는 파일로 다룸)을 묶었다.

@@ linux-d4-sec8-p8-2
1. CPU 사용률은 /proc/stat 누적값 두 개의 차이로 구한다.
2. 실제로 더 쓸 수 있는 메모리는 page cache 까지 고려한 MemAvailable 이다.
3. 오차 없는 주기는 clock_nanosleep 의 TIMER_ABSTIME 으로 맞춘다.
4. /sys/block/*/stat 의 섹터는 512 바이트 단위다.

@@ linux-d4-sec8-inline
- `sysmon`: procfs · sysfs 로 만든 시스템 모니터 (종합 실습).
- `/proc/stat`: CPU 시간 누적값 파일.
- `/proc/meminfo`: 메모리 정보 파일.
- `/sys/block/sda/stat`: 디스크 sda 의 I/O 통계 (7번째 값 = 쓴 섹터).
- `/sys/class/net/enp0s3/statistics/rx_bytes`: 네트워크 장치가 받은 바이트 누적값.
- `src/sysmon.c`: sysmon 소스.
- `/proc`: procfs 경로.
- `/sys`: sysfs 경로.
- `edge_pipeline.c`: Day 5 에서 5일간의 결과를 합쳐 만들 종합 프로그램.
- `total`: CPU 전체 시간 누적값.
- `idle`: CPU 가 놀았던 시간 누적값.
- `/proc/`: procfs 아래 경로의 시작.
- `/sys/block/*/stat`: 모든 블록 장치의 stat 파일 (섹터는 512 바이트).

@@ linux-d4-src-module-mysysfs.c
