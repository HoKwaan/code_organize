@@ eio-d5-sec1-1
예제 01 은 DHT11 을 사용자 공간에서 직접 읽어 보는, 일부러 실패를 보려고 만든 예제다. DHT11 비트는 High 26~28 µs 가 0, 70 µs 가 1 이라 수십 µs 차이를 구분해야 한다. 배선은 S → GPIO4, + → 3V3 이고, dtoverlay=dht11 이 켜져 있으면 GPIO4 가 busy 라 overlay 전에 한다.
- `decode()`: High 폭 목록의 마지막 40개를 50 µs 보다 길면 1 로 보고 5바이트로 모은다. 앞 4바이트 합이 다섯째 바이트(체크섬)와 다르면 -1, 40개가 안 되면 -(100 + 개수)를 돌려주고, 맞으면 b[0] 습도 · b[2] 온도다.
- `cfg()`: 출력(처음 INACTIVE) 또는 입력(풀업, 필요하면 양쪽 엣지 검출) 라인 설정을 만든다.
- `read_once()`: 라인을 출력으로 바꿔 20 ms Low 시작 신호를 주고 입력으로 바꿔 센서 응답을 받는다. 폴링 모드는 8 ms 동안 get_value 를 계속 읽어 값이 바뀔 때 `now_ns()` 로 시각을 찍는데, 읽은 순간이 아니라 "지금" 이라 늦게 찍힐 수 있다. 엣지 모드(`-e`)는 poll 로 기다려 커널이 찍은 이벤트 타임스탬프로 High 폭을 잰다.
- main: `-e` 엣지, `-n 횟수`(기본 10)를 받는다. 엣지 80개가 한꺼번에 오므로 칩을 직접 열고 이벤트 버퍼를 256 으로 넉넉히 잡아 요청한다(기본은 라인당 16개). 2초 간격으로 읽어 OK · 체크섬 오류 · 비트 부족을 찍고 끝에 성공 횟수를 낸다.

가끔 성공하는 것이 더 위험하다. 시험 때는 되고 현장에서 틀린다.

@@ eio-d5-sec1-5
드라이버가 제대로 붙었는지 확인하는 명령이다.
- `dmesg | grep -i dht`: 커널 로그에 dht 드라이버 메시지가 있는지 본다.

- `cat …/in_humidityrelative_input`: 41000 = 41 % 다.

IIO(Industrial I/O)는 센서 값을 /sys/bus/iio 아래 파일로 내놓는 커널의 공통 틀이라 가속도 · 조도 · ADC 도 같은 모양으로 읽는다.

@@ eio-d5-sec1-6
커널 dht11 드라이버(IIO)를 읽는 모듈의 헤더다. overlay 를 켜면 /sys/bus/iio/devices/iio:deviceN/ 에 in_temp_input(밀리 °C, 23000 = 23.0 °C)과 in_humidityrelative_input(밀리 %, 45000 = 45 %)이 생긴다. `dht_t` 는 찾은 IIO 장치 디렉터리와 연속 실패 횟수를 담고, `dht_open()` 은 장치를 찾으면 0 · 없으면 -1(overlay 확인), `dht_read()` 는 성공 0 · 3번 재시도 후 실패 -1 을 돌려준다. 오늘부터 .h 에는 선언만 두고 구현은 .c 에 둔다.

@@ eio-d5-sec1-7
dht.h 의 구현이다.
- `read_long()`: 디렉터리/이름 파일을 열어 정수 하나를 읽는다. 드라이버가 읽기에 실패하면 read 가 EIO · ETIMEDOUT 으로 실패해 -1 이 된다.
- `dht_open()`: 장치 번호 N 은 부팅마다 바뀔 수 있어 `glob("/sys/bus/iio/devices/iio:device*/in_humidityrelative_input")` 로 습도 파일이 있는 장치를 찾고, 마지막 '/' 앞까지를 장치 디렉터리로 저장한다.
- `dht_read()`: 온도와 습도 파일을 둘 다 읽으면 1000 으로 나눠 °C 와 % 로 돌려주고 실패 횟수를 0 으로 되돌린다. 실패하면 0.3초 쉬고 최대 3번 다시 시도하며, 그래도 안 되면 fails 를 늘리고 -1 이다.

@@ eio-d5-sec1-t1
DHT11 한 번 읽기의 단계와 길이다. Pi 가 18 ms 이상 Low 로 시작 신호를 주고, 입력으로 바꿔 놓으면 풀업으로 20~40 µs High 가 된다. @@ eio-d5-sec1-t2

GPIO17 LED 와 GPIO5 버튼을 커널 장치로 만드는 Device Tree overlay 소스다. `/dts-v1/;` · `/plugin/;` 은 overlay 라는 표시이고, `compatible = "brcm,bcm2711"` 은 Pi 4 용이라는 뜻이다.
- `fragment@0`: target 이 &gpio 노드라, 그 아래에 `eio_key_pins` 핀 설정을 덧붙인다. `brcm,pins = <5>` 핀 5 를 `brcm,function = <0>` 입력, `brcm,pull = <2>` 풀업으로 만든다.

@@ eio-d5-sec3-3
lcd.h 의 구현이다. HD44780 의 타이밍은 "최소 시간" 만 있어서(E 폭 ≥ 450 ns, 명령 뒤 ≥ 37 µs, clear 뒤 ≥ 1.52 ms) 늦어지는 것은 괜찮고, 그래서 스케줄링 지연이 있는 사용자 공간에서도 동작한다. DHT11 과 다른 점이다.
- `PINS[]`: RS · E · D4 · D5 · D6 · D7 = GPIO12 · 16 · 20 · 21 · 26 · 22. enum 으로 배열 위치를 이름 붙였다.
- `struct lcd`: GPIO 요청과 여섯 핀의 현재 값 배열. 내용은 이 파일 안에만 있다(불투명 포인터).
- `us_sleep()`: nanosleep 이 신호(EINTR)로 끊기면 남은 시간만큼 다시 자서 Ctrl+C 로 짧아지지 않게 한다.
- `apply()`: 값 배열을 한 번에 핀에 쓴다.
- `nibble()`: 4비트를 D4~D7 에 올리고 E 를 High → Low 로 내린다. 떨어지는 순간 LCD 가 읽는다.
- `send()`: RS 를 정하고 위 4비트 → 아래 4비트 순서로 니블 두 번 보낸 뒤 50 µs 쉰다.
- `lcd_cmd()` · `lcd_putc()`: RS = 0 명령, RS = 1 글자.
- `lcd_clear()`: 0x01 을 보내고 2 ms 기다린다. `lcd_goto()`: 0x80 | (2행이면 0x40) + 열 로 커서를 옮긴다. `lcd_puts()`: 글자를 차례로 쓴다.

@@ eio-d5-sec7-1
envmon 을 부팅하면 자동으로 실행하는 systemd 서비스 파일이다. 맨 위 주석에 사용 순서(사용자 이름 바꾸기 → /etc/systemd/system 에 복사 → daemon-reload → enable --now → journalctl 로 로그 보기)가 있다.
- `[Unit] Description=`: systemctl status 등에 보이는 설명.
- `Type=simple`: ExecStart 프로세스가 곧 서비스다.
- `User=pi`: root 가 아닌 내 계정으로 실행한다. gpio · i2c 그룹 권한으로 충분하다.
- `WorkingDirectory=`: 실행 폴더이자 CSV 가 생기는 곳.
- `ExecStart=`: envmon 을 CSV 절대 경로와 함께 실행한다.
- `KillSignal=SIGTERM` · `TimeoutStopSec=5`: systemctl stop 이 SIGTERM 을 보내고, envmon 핸들러가 출력을 끄고 GPIO 를 반납한다. 5초 안에 안 끝나면 강제로 끝낸다.
- `Restart=on-failure` · `RestartSec=3`: 비정상 종료(코드 ≠ 0, 신호로 죽음) 때만 3초 뒤 다시 시작한다.
- `[Install] WantedBy=multi-user.target`: enable 하면 부팅 순서에 들어간다.

ExecStop 을 따로 쓰지 않는 것은 envmon 이 SIGTERM 을 받아 스스로 정리하기 때문이다. 프로그램 밖 스크립트는 프로그램이 이미 죽은 뒤라 무엇을 켜 두었는지 모른다.

@@ eio-d5-src-dht.c
dht.h 구현 원본이다. 파일에서 정수 하나를 읽는 `read_long()`, glob 으로 습도 파일이 있는 IIO 장치를 찾는 `dht_open()`, 밀리 단위 값을 1000 으로 나누고 실패하면 0.3초 간격으로 3번 재시도하는 `dht_read()` 를 담는다. 줄별 설명은 1-5 예제 02 를 본다.

@@ eio-d5-src-dht.h
DHT11(IIO) 모듈 헤더 원본이다. 장치 디렉터리와 연속 실패 수를 담는 `dht_t` 와 `dht_open()` · `dht_read()` 선언만 둔다. 줄별 설명은 1-5 예제 02 를 본다.

@@ eio-d5-src-eio-overlay.dts
직접 쓴 Device Tree overlay 원본이다. GPIO5 를 입력 + 풀업으로 설정하고, GPIO17 을 gpio-leds(eio:green, 기본 heartbeat)로, GPIO5 를 gpio-keys(active-low, KEY_ENTER, 디바운스 20 ms)로 만든다. 줄별 설명은 2-3 eio-overlay.dts 를 본다.

@@ eio-d5-src-envmon.c
종합 프로젝트 envmon 원본이다. sensor(온습도 · 조도) · proximity(거리) · control(버튼 · 판단 · 출력) · display(LCD · CSV) 네 쓰레드가 mutex 와 조건 변수로 지키는 공유 상태 하나를 주고받고, main 은 SIGINT · SIGTERM 을 기다렸다가 출력을 끄고 정리한다. 줄별 설명은 5-3 완성본 envmon.c 를 본다.

@@ eio-d5-src-envmon.service
envmon 의 systemd 서비스 파일 원본이다. 내 계정으로 실행하고, SIGTERM 으로 멈추며, 비정상 종료 때만 3초 뒤 다시 시작하고, enable 하면 multi-user.target 부팅 순서에 들어간다. 줄별 설명은 7-1 systemd 서비스를 본다.

@@ eio-d5-src-gpio_common.h

@@ eio-d5-src-lcd.c
